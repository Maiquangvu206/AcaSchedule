# Xoay vòng API key: Gemini + OpenRouter

> **Quản lý key trên web:** admin có thể thêm/tắt/xoá key và xem lượt truy vấn tại
> `/admin/ai` — xem [docs/ai-admin.md](./ai-admin.md). Key khai báo trong biến môi
> trường dưới đây vẫn được dùng làm **dự phòng** khi database chưa có key.

AI Service dùng **hai nhà cung cấp** để chức năng AI không bao giờ lỗi:

```
Gemini   (nhiều project → nhiều key)  ─┐
                                       ├─► xoay vòng mỗi request ─► câu trả lời
OpenRouter (nhiều tài khoản → nhiều key)┘
                                       └─► tất cả lỗi ─► câu trả lời dự phòng (HTTP 200)
```

- **Trong một nhà cung cấp**: key được xoay vòng, key hết quota bị tạm nghỉ.
- **Giữa hai nhà cung cấp**: nếu Gemini lỗi hoàn toàn, tự chuyển sang OpenRouter và ngược lại.
- **Tất cả đều lỗi**: trả lời bằng thuật toán dự phòng — sinh viên **không thấy lỗi**.

Bạn nên cấu hình **~5 key mỗi bên** để có nhiều quota dự trữ.

---

## 1. Gemini — tạo nhiều key

Mỗi **project** trên [Google AI Studio](https://aistudio.google.com/apikey) có quota
riêng. Để nhân quota lên N lần, tạo N project → mỗi project 1 API key.

```
Project acaschedule-1 → key A
Project acaschedule-2 → key B
…
```

> Không tạo nhiều key trong **cùng một project** — chúng dùng chung quota.

Render → **acaschedule-ai → Environment**:

```
GEMINI_API_KEYS=keyA,keyB,keyC,keyD,keyE
```

`GEMINI_API_KEY` (key đơn) vẫn được hỗ trợ và được **nối vào cuối** danh sách.
Key trùng nhau tự loại bỏ.

---

## 2. OpenRouter — tạo nhiều key

1. Đăng ký / đăng nhập <https://openrouter.ai>
2. **Keys** → **Create Key** → lưu lại (chỉ hiện một lần)
3. Lặp lại với tài khoản thứ hai, thứ ba… nếu muốn nhân quota
4. Chọn model: **Models** → tìm model → copy ID (ví dụ `google/gemini-2.0-flash-001`)

Render → **acaschedule-ai → Environment**:

```
OPENROUTER_API_KEYS=key1,key2,key3,key4,key5
OPENROUTER_MODEL=google/gemini-2.0-flash-001
```

Gợi ý model (đổi bằng `OPENROUTER_MODEL`, không cần sửa code):

| Model ID | Ghi chú |
|---|---|
| `google/gemini-2.0-flash-001` | Nhanh, rẻ, tiếng Việt tốt (mặc định) |
| `openai/gpt-4o-mini` | Chất lượng cao, giá thấp |
| `meta-llama/llama-3.3-70b-instruct` | Mã nguồn mở |
| `meta-llama/llama-3.3-70b-instruct:free` | Miễn phí, giới hạn request/ngày |

> Model `:free` có hạn mức riêng theo tài khoản và có thể xếp hàng lâu — chỉ nên
> dùng làm dự phòng, không phải lựa chọn chính.

`OPENROUTER_API_KEY` (key đơn) cũng được hỗ trợ, nối vào cuối pool.

---

## 3. Thứ tự ưu tiên

```
AI_PROVIDER_ORDER=gemini,openrouter
```

- Danh sách được **xoay vòng mỗi request**, nên tải chia đều cho cả hai bên.
- Nếu một bên lỗi hoàn toàn, request chuyển ngay sang bên kia.
- Bỏ trống biến này → mặc định `gemini,openrouter`.

Muốn dồn hết sang OpenRouter (ví dụ Gemini hết hạn mức cả tháng):

```
AI_PROVIDER_ORDER=openrouter,gemini
```

---

## 4. Cơ chế xoay vòng

| Tình huống | Gemini | OpenRouter |
|---|---|---|
| Request bình thường | Round-robin key | Round-robin key |
| Hết quota | **429** → nghỉ 60s, sang key kế | **429 / 402** → nghỉ 60s, sang key kế |
| Key sai / bị khoá | **401/403** → nghỉ 600s | **401/403** → nghỉ 600s |
| Lỗi máy chủ / timeout | Retry 1 lần, backoff 1–4s | Retry 1 lần, backoff 1–4s |
| Sai model / request hỏng | **400/404** → báo lỗi, không xoay | **400/404** → báo lỗi, không xoay |
| Câu trả lời bị cắt | Tự gọi tiếp (`MAX_TOKENS`) | Tự gọi tiếp (`finish_reason=length`) |
| Cả hai nhà cung cấp lỗi | — | Trả câu trả lời **dự phòng**, HTTP 200 |

Cooldown nằm trong RAM của tiến trình AI → restart service sẽ reset.
Keyword trong log Render:

```
Gemini key #1 out of quota (429) — cooling down 60s, trying next key
OpenRouter key #2 out of quota/credits (402) — cooling down 60s, trying next key
AI provider gemini failed: …          ← chuyển sang nhà cung cấp kia
AI answer generated by openrouter     ← cho biết bên nào đã trả lời
```

## 5. Kiểm tra cấu hình

```
GET https://acaschedule-ai-quju.onrender.com/health
```

```json
{
  "status": "ok",
  "gemini_configured": true,
  "gemini_keys": 5,
  "openrouter_configured": true,
  "openrouter_keys": 5,
  "openrouter_model": "google/gemini-2.0-flash-001",
  "model": "gemini-3.5-flash",
  "provider_order": ["gemini", "openrouter"]
}
```

- `gemini_keys` / `openrouter_keys` = số key đã nạp vào pool.
- Nếu một bên bằng `0` → biến môi trường chưa được nạp (kiểm tra tên biến, dấu phẩy, deploy lại).

---

## 6. Lưu ý

- **Không** commit key vào repo. Chỉ đặt trong Render Environment hoặc `.env` local (đã gitignore).
- Key lưu dạng thô trong env — hạn chế thành viên có quyền vào Render dashboard.
- OpenRouter tính tiền theo token; đặt **credit limit** cho từng key trong dashboard để tránh vượt ngân sách.
- Gemini miễn phí có quota theo **project** và theo **ngày**; ~5 key thường đủ cho lớp học nhỏ.
- Nếu `AI_PROVIDER_ORDER` chỉ còn một bên, hệ thống vẫn hoạt động nhưng mất khả năng dự phòng.
- Đổi model: sửa `GEMINI_MODEL` / `OPENROUTER_MODEL` rồi Manual Deploy (không cần sửa code).
